# ☁️ 云端执行部署指南（关机也能准时收到日报）

> 目标：让日报在**您的电脑完全关机**时也能准时生成并送达邮箱。
> 原理：把 `scripts/standalone_report.py`（独立离线脚本）放到云端定时执行；
> 它不依赖 DSH、不依赖您的电脑，采集→分析→生成→发信全部在云端完成。
> 本目录已包含全部可部署文件：`.github/workflows/daily_report.yml`（GitHub Actions）、`.gitignore`。

---

## 🔐 安全模型（您的核心关切）

| 凭据 | 存放方式 | 安全保证 |
| :--- | :--- | :--- |
| `DEEPSEEK_API_KEY` | GitHub **Secrets**（环境变量注入） | GitHub 以 AES-256 加密存储；日志自动脱敏；**不写入任何代码/仓库文件** |
| `SMTP_AUTHCODE`（邮箱授权码） | GitHub **Secrets** | 同上 |
| `SMTP_SENDER` / `SMTP_RECIPIENT`（邮箱地址） | GitHub **Secrets** | 同上 |

附加保证：
1. **仓库必须设为 Private（私有）**——代码与工作流只有您可见；
2. **脚本只从环境变量读取凭据**（`standalone_report.py` / `send_report.py` 已支持 `DEEPSEEK_API_KEY`、`SMTP_*`），云端运行无需本地 `config/smtp_config.json`；
3. `.gitignore` 已排除 `config/smtp_config.json`、`.credentials.yaml`、`reports/`、`logs/`——**提交时这些文件不会被推上去**（提交前仍建议 `git status` 自查）；
4. 工作流 `permissions: contents: read`（最小权限，云端进程不写仓库）；
5. 若怀疑泄露：QQ 邮箱可随时**重置授权码**、DeepSeek 平台可**删除/轮换 API Key**，两者均为一次性凭据，可随时作废重发。

> ⚠️ 关键纪律：**任何情况下不要把授权码/API Key 写进代码、提交信息、Issue、评论或公开仓库**。
> GitHub 会扫描并告警硬编码密钥（Push Protection），但请主动遵守。

## 🚀 方案 A：GitHub Actions（免费、无需服务器，推荐）

### 前提
- 一个 GitHub 账号（https://github.com 免费注册）；
- 本机已安装 `git`（已确认 2.53.0）。

### 步骤

**1. 创建私有仓库**
- GitHub 网页 → New repository → 名称如 `xwlb-report` → **选 Private** → 不要勾选任何初始化文件。

**2. 在本地把工作区推上去**（在 `D:\CTYJ\DeepSeek\Harness\News` 执行）：
```powershell
git init
git add .
git status            # 确认 config/smtp_config.json 与 logs/ 等不在列表里（被 .gitignore 排除）
git commit -m "新闻联播日报：云端可部署版（凭据仅走 Secrets）"
git branch -M main
git remote add origin https://github.com/<你的用户名>/xwlb-report.git
git push -u origin main
```

**3. 配置 Secrets**（仓库页面 → Settings → Secrets and variables → Actions → New repository secret，共 4 个）：
| Secret 名 | 值 |
| :--- | :--- |
| `DEEPSEEK_API_KEY` | 您的 DeepSeek API Key（与 `C:\Users\CTYJ\.dsh\.credentials.yaml` 中一致） |
| `SMTP_SENDER` | `1761920786@qq.com` |
| `SMTP_AUTHCODE` | 您的 QQ 邮箱 SMTP 授权码 |
| `SMTP_RECIPIENT` | `1761920786@qq.com`（多个用英文逗号分隔） |

**4. 验证**
- Actions 页面 → 左侧 `daily-xinwenlianbo-report` → **Run workflow**（手动触发一次）→ 等 2-5 分钟 → 查收邮件；
- 确认后再等每日定时（`35 13 * * *` = 北京时间 21:35）。

### 时间与网络说明
- 定时为 **13:35 UTC = 21:35 北京时间**，与当日《新闻联播》19:00 播出、19:47 新浪 7x24 上线的时间线匹配；
- GitHub 公共运行器位于海外，`sina.com.cn`、`smtp.qq.com:465`、DeepSeek API 均可访问；
  若偶尔采集失败，脚本会自动生成「数据缺失说明」邮件并照常推送（不静默）。

## 🚀 方案 B：腾讯云函数 SCF（国内网络更稳，可选）

若您更倾向国内云（对 smtp.qq.com / 新浪接口的网络更友好）：
1. 注册腾讯云 → 云函数 SCF → 新建函数，运行时 Python 3.11，**上传 `scripts/standalone_report.py` 与 `send_report.py`**；
2. 环境变量：`DEEPSEEK_API_KEY`、`SMTP_SENDER`、`SMTP_AUTHCODE`、`SMTP_RECIPIENT`（SCF 控制台环境变量加密保存）；
3. 触发器：定时触发器 `cron 表达式` = `0 35 21 * * * *`（每天 21:35）；
4. 函数入口改为调用 `standalone_report.main()`（脚本已用 `if __name__ == "__main__"` 保护，可直接 `from standalone_report import main`）；
5. 同样遵守：函数代码不硬编码凭据、日志不打印凭据。

## ⚠️ 双发处理（重要）

云端生效后，**本机两条定时路径（DSH 看板 21:30、Windows 计划任务 21:35）应停用**，否则电脑开机时会与云端重复发信。
- 停用 Windows 计划任务（管理员/当前用户）：
  ```powershell
  schtasks /change /tn "NewsReportDaily-Offline" /disable
  ```
- DSH 看板任务「每日《新闻联播》日报生成与推送」：在看板中**取消**或保留为手动（如需保留看板验收流程，可把执行方式改为手动触发/认领，或在云端发送后跳过推送）。
- 本机脚本仍可用于手动补跑：`python scripts/standalone_report.py --date YYYY-MM-DD --dry-run`。

## 📌 故障排查
- 邮件未收到：Actions 页面查看运行日志（凭据已被 GitHub 脱敏，日志安全）；先手动 `Run workflow` 复现；
- 提示 `模型 ... 返回空内容`：脚本会自动加大 token 重试并降级模型，通常自愈；
- 提示 `未找到 DEEPSEEK_API_KEY`：检查 Secrets 名称是否拼写一致（`DEEPSEEK_API_KEY`）。
